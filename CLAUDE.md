## Приложение `site/`

- Запуск: `cd site && npm install && npm run dev`. Подробности и структура — в `site/README.md`.
- Node.js на этой машине установлен портативно в `%LOCALAPPDATA%\Programs\node` (добавлен в PATH пользователя; в Git Bash при необходимости `export PATH="/c/Users/cr7um_geelv3s/AppData/Local/Programs/node:$PATH"`).
- Контент (резюме, контакты, проекты, листы) — JSON в `site/content/`, читается только через `site/lib/content.ts`; типы в `site/lib/types.ts`. Это точка подключения будущей админки/БД — страницы менять не придётся.
- Постраничный переход на всём сайте: `ScreenPager` (подключён в `app/layout.tsx`) плавно, ~1 с, листает экраны `[data-screen]` колесом/PageDown/стрелками; экран выше окна сначала прокручивается обычно. Затемнения (вуали) при перелистывании нет — заказчик просил убрать: при переходе кнопкой со стрелкой его не было, и разница бросалась в глаза. Сами экраны не анимировать: opacity/transform на секции меняют цвет стеклянных карточек (backdrop-filter) и ломают `position: fixed` внутри (кнопка `Cta`). CSS scroll-snap больше не используется. На мобильных и низких окнах (<761 px по ширине или <560 px по высоте) отключено.
- Ссылки-якоря на экраны (кнопка «Резюме» на обложке, кнопка со стрелкой) перехватывает `ScreenPager` и листает тем же переходом, что и колесо (~1 с, та же кривая) — у браузерной прокрутки по якорю переход был резче, заказчик просил одинаково.
- Кнопка со стрелкой «к следующему экрану» — одна на всю главную: `components/NextCta.tsx` (в `app/page.tsx`, вне секций). Раньше у каждого раздела была своя (`Cta` внутри `Stagger`): при перелистывании она пряталась, а следующая ждала каскад своего раздела (у проектов 7 с) — заказчик просил, чтобы кнопка не исчезала и не «загружалась». Впервые выходит, когда доиграл каскад текущего раздела (`--cards-done` + `data-reveal-at` от `Stagger`), дальше видна сразу на всех экранах, у которых есть следующий (кроме обложки); текущий экран — `Stagger` с `data-visible`. Прежний `Cta` остался только в копии резюме для прогрева видеокарты (шейдер размытия под кнопкой).
- Каскады разделов главной играют только при первом просмотре (`once` у `Stagger`, набор сыгранных — в памяти модуля): при возврате со страницы проекта всё сразу на местах (`data-reveal="done"`), заново анимации проигрывает только перезагрузка страницы. Проверка всего этого — `npm run check:nav`.
- Адрес следует за экраном: `ScreenPager` после остановки прокрутки ставит хеш текущего экрана (`#resume`, `#projects`, `#contacts`, `#overview`; у экрана без `id` хеш снимается) через `history.replaceState` — иначе после кнопки «Резюме» в адресе навсегда оставался `#resume`, и перезагрузка возвращала к резюме с любого экрана. Чужой хеш (`#sheet-N`) не трогает. Проверка — `npm run perf:reload`.
- Фон главной — свечение из двух слоёв (`body::before` и `body::after`, по два пятна), которые плывут навстречу друг другу (`glow-drift-a` 26 с, `glow-drift-b` 34 с, только `transform` на своём слое; включается через `body:has([data-home])`, `data-home` стоит на `<main>` главной). Пятна — вытянутые эллипсы с затуханием в 8 ступеней, близким к гауссову: с линейным градиентом читался край, и заказчику казалось, что плавают цельные круги. Слои больше окна (`inset: -30%`) — при сдвиге и повороте край в окно не попадает; менять амплитуду только вместе с этим запасом. На странице проекта фон неподвижен — там видеокарта занята макетом.
- Каскад карточек проектов (не откатывать): пока он играет (5,3 с — `busyMs` у `Stagger`, по умолчанию 3 с), фоновая подготовка не идёт. Раньше отметка «занято» кончалась на 3-й секунде, и прогрев видеокарты попадал во въезд школы (кадры 66–142 мс), а курсор, оставшийся после прокрутки над въезжающей карточкой, считался наведением и запускал three.js (134 мс блокировки). Теперь подготовка по наведению и шаги сборки макетов ждут конца анимаций — `idlePause({ calm: true })` (`isBusy`), в отличие от `quiet` ввод им не мешает. Замер — `npm run perf:cards` (`COLD=1`, `TRACE=1`).
- Переходы между страницами — View Transitions (`components/SheetTransition.tsx`, CSS в конце `globals.css`): `<PageSheet>` — самая внешняя обёртка страницы (иначе React не запускает enter/exit), `<ProjectIcon>` — общий элемент «карточка на главной ↔ иконка проекта». Тип перехода задаёт `transitionTypes` у `Link` (`proj-open`, `proj-close`, `proj-next`, `proj-prev`). `ViewTransitionScroll` (в `layout.tsx`) перед обновлением DOM ставит прокрутку к месту назначения — React именует только видимые в окне элементы. При возврате по ссылке с `data-nav="proj-close"` каскад карточек проектов не играет (`Stagger skipAfter`, отметка в `lib/arrival.ts`) — карточки сразу на местах, иконка прилетает в свою. Страница проекта раскрывается кругом с мягким краем (маска с `@property --vt-r`), затем листы карусели по очереди въезжают справа (`--slides-delay` в `SheetGallery`: 1.1 с после перехода, 0.25 с при обычном открытии). В `npm run dev` переходы часто не играют (нет предзагрузки страниц) — проверять на `npm run build && npm run start`.
- Страницы: `/` (экраны: интро, резюме, проекты, контакты), `/projects/{flat,school,tower}` — два экрана: 1) иконка + описание + карусель листов А3 в стеклянной панели (колесо листает листы, на краю ленты страница не уезжает до паузы; полноэкранный просмотр с клавиатурой/свайпом и ссылкой `#sheet-N`); 2) `#overview` — планшет проекта и блоки соседних проектов (по кругу) на сетке с равными отступами. На первом экране справа внизу — та же кнопка со стрелкой, что на главной (`components/ScreenDownCta.tsx`, стили `Cta.module.css`): ведёт к `#overview` тем же переходом `ScreenPager`, на последнем экране прячется; стоит в `<main>` вне экранов (просьба заказчика). На мобильных и низких окнах (<761 px по ширине или <560 px по высоте) постраничная прокрутка отключена. 404.
- 3D-макет на странице проекта — `components/ProjectModel.tsx` (three.js, грузится динамически): после перехода иконка «ложится» (камера сначала строго сверху — 3D-карточка совпадает с картинкой 1:1), из линий плана «печатается» здание (срез по высоте + светящийся контур), потом его можно вращать мышью (OrbitControls, без зума — колесо листает экраны; в полноэкранном просмотре приближение ведём сами — плавным доездом за `ZOOM_EASE`, `enableZoom` у OrbitControls выключен, иначе шаг колеса проходит мимо цикла и виден только при следующем движении). Нажатие (без перетаскивания) или Enter открывает макет на весь экран: нативный `<dialog>` с размытым `::backdrop`, холст переезжает в него, карточка плавно «перелетает» со своего места в центр и вписывается во весь экран (анимируется рамка карточки для `setViewOffset` и расстояние камеры); там его можно вращать (и на сенсорных экранах) и приближать колесом (`ZOOM_IN`/`ZOOM_OUT`), а с зажатым колесиком — перемещать (панорама, как в Revit; просьба заказчика): точка вращения `pivot` едет за мышью в плоскости экрана и плавно доезжает за `PAN_EASE`, камера — вместе с ней, дальше вращение и приближение идут вокруг нового места; пределы — края карточки и высота здания; средняя кнопка у OrbitControls отключена (`mouseButtons`), автопрокрутка браузера погашена. Все расчёты камеры — относительно `pivot` (`fromPivot`); при закрытии просмотра он за время посадки возвращается в центр карточки (`pivot0` в `morph`). На странице (не на весь экран) панорамы нет. Закрытие — повторное нажатие, Esc или крестик, с обратным перелётом. Подписи под макетом нет. Геометрия — `public/projects/<slug>/model.json`, строится `npm run models` (`scripts/make-models.py`, нужны `numpy` и `opencv-python-headless`) из `public/icons/<slug>-dark.png`: этажность, высота этажа и незастроенные области (двор школы) — в `PROJECTS` в скрипте; контрольные картинки — `site/.model-debug/`. Детализация по планшетам проектов: толстые линии плана — стены, тонкие — перегородки, а тонкие на внешнем контуре — остекление (низ — глухое ограждение `rail`, выше стекло с переплётами); на глухих участках фасада — окна с рамами (`windows`: у школы узкие высокие, у башни квадратные; `blank` — без окон, концертный зал); парапет на кровле; у башни рамка-пергола на стойках (`canopy`); круглый блок школы поднят на V-образные опоры (`lifted`). Тот же скрипт пишет `plate.png` — иконку без надписей и линии под названием: пока карточка ложится, исходная картинка поверх неё гаснет, а сам рисунок плана (`setPlate`) уходит, как только пошла «печать», — здание стоит на чистой земле; земля под рисунком — отдельная плоскость цветом фона самой картинки (пиксель у левого края `plate.png`), иначе вместо бордового открывалась бы подсвеченная плита карточки; при обратной анимации и рисунок, и надписи проявляются снова. Углы 3D-карточки — дуги радиусом `CARD_RADIUS` (как у PNG иконки). Камера вращается вокруг центра карточки, а `setViewOffset` держит его в центре исходной иконки — 3D-карточка того же размера и на том же месте. Уход на главную («← Портфолио» или кнопка «Назад»): сначала обратная анимация (здание разбирается, камера возвращается строго сверху), затем плоская иконка улетает переходом `proj-close` (`router.push`/`router.replace`). «Назад» ловится через хук `window.__popstateHook` — слушатель `popstate` из `app/layout.tsx` (`next/script` beforeInteractive), он обязан стоять раньше роутера Next. Для остальных ссылок с `data-nav` сцена прячется мгновенно.
- Закрытие полноэкранного макета (не откатывать): обратный перелёт — `LAND_TIME` 1 с по кривой `easeLand` (короткий разгон, долгое мягкое торможение; открытие — прежние `MORPH_TIME`/`easeInOut`). За время посадки камера возвращается к исходному наклону (`FINAL_POLAR`), а автовращение включается снова и набирает скорость с нуля за `SPIN_RAMP` — макет садится в привычное положение и продолжает крутиться (просьба заказчика). После посадки буфер холста ещё `LAND_HOLD` остаётся полноэкранным (`holdSizeUntil` в `applySize`; холст растянут по месту, пропорции задаёт камера) — раньше в момент приземления буфер пересоздавался дважды (сразу и через `RESIZE_MIN_GAP` от `ResizeObserver`): кадры 70 и 118 мс, заказчик видел рывок. `::backdrop` диалога — постоянное размытие, проявляется через `opacity`: при анимации радиуса размытия весь экран размывался заново на каждом кадре (кадры по 40 мс в начале закрытия). Замер — `npm run perf:full` (`ZOOM=1`, `SHOT=1`): интервалы кадров при открытии и закрытии, сейчас без кадров дольше 25 мс.
- Карточка-земля макета: по границе — белая обводка (полоса `CARD_RIM_WIDTH` на верхней грани, проявляется вместе с линиями — `setLineFade`; линия в 1 px по ребру сливалась с белым торцом), обводка чуть выступает наружу (`CARD_RIM_OVERHANG`) — иначе между ней и торцом виден тёмный шов; торец плиты сероватый (`CARD_SIDE`): белым он сливался с обводкой в одно целое (`CARD_RIM` = белый обложки `#e9e9ed` в `modelScene.ts`) — просьбы заказчика; верх закрыт плоскостью `ground` цветом фона иконки.
- Музыкальная школа — **макет из экспорта Revit (IFC)**: `scripts/make-school-ifc.py` (нужны `ifcopenshell`, `numpy`, `opencv-python-headless`; путь к IFC — аргумент, `SCHOOL_IFC` или по умолчанию `Desktop\Revit\Projects\Проект Школы (Art Brodsky)\Проект Школы (Art Brodsky).ifc`, в репозиторий файл не кладём). Скрипт триангулирует IFC, раскладывает элементы по материалам ProjectModel (класс IFC + цвет стиля: wall, panel, slab, glass, frame, metal, stair, wood, rail…), упрощает сеткой вершин в меру (`GRID`/`GRID_SMALL`, у дверей/окон/ограждений крупнее и без кусков мельче `MIN_PIECE` — ручек, петель): треугольники почти не влияют на кадр (246 тыс. и 73 тыс. давали одинаковые 17 мс), а детализация при приближении важна, совмещает с карточкой (сдвиг IFC → план подбирается корреляцией стен 1-го этажа с `school-plan.json`, дальше его `transform`; ноль по высоте — отметка 1-го этажа, карточка и есть земля и пол: по нижней точке IFC здание вставало на невидимый цоколь фундаментной плиты и казалось висящим; всё, что целиком на уровне земли и ниже, из макета выброшено — иначе внутри здания вместо бордовой земли светлая плита 1-го этажа, да ещё ровно в плоскости карточки), считает рёбра, контур кровли и срез «печати», сжимает GLB `gltfpack` (meshopt + квантование `-vp 16` — при 14 битах плоскости «дрожат» и секущая плоскость рвёт их край; `SIMPLIFY < 1` включил бы `-si`, но упрощение геометрии только портит вид вблизи и скорости не даёт — сейчас 1; в `ProjectModel` подключён `MeshoptDecoder`, материалы ищутся по имени материала GLB). - Двухкомнатная квартира — **макет интерьера из экспорта Revit (IFC)**: `scripts/make-flat-ifc.py` (`npm run models:flat`; те же зависимости, что у школы; путь к IFC — аргумент, `FLAT_IFC` или по умолчанию `assets/revit files/Interiors working drawings/двухкомнатная квартира/двухкомнатная квартира.ifc`, в git не кладём — `.gitignore`). - Производительность (не откатывать): `ProjectModel` — плотность пикселей не выше `MAX_DPR` и снижается при медленных кадрах только в покое (менять чёткость посреди анимации заметно), кадры не чаще `FRAME_MIN`, в покое (макет не вращается) не перерисовывает, карта теней пересчитывается только при сборке/разборке здания (`shadowMap.autoUpdate = false`). Буфер холста пересоздаётся не чаще `RESIZE_MIN_GAP` (при зуме страницы Ctrl+колесом размер меняется на каждый шаг), а `adaptDpr` не трогает его во время движения и сразу после смены размера — иначе плотность скачет и каждый скачок это пауза. - Панель листов на странице проекта — градиентный фон (`.sheetsSection::before` в `page.module.css`): широкая полоса (200 % ширины) из мягких радиальных пятен в цветах проекта (`--p-bg`, `--p-ink`) и сайта, которая едет под листами вместе с лентой — `SheetGallery` ставит `--track-p` (0…1) на панель `[data-sheets-panel]`, а слой двигается только через `transform` (растрируется один раз). У самих листов `backdrop-filter` снят: картинка закрывает лист целиком, а каждый фильтр — отдельная поверхность для компоновщика.

У башни пока SVG-заглушки из `npm run placeholders` (скрипт больше не трогает flat и school). Пока чертежи не готовы, карусель заблокирована (поле `underConstruction` в `projects.json` → `locked` у `SheetGallery`): листы размыты (`filter: blur`, статично), `inert` — не нажимаются и не открываются, ссылка `#sheet-N` тоже не открывает, подсказки «крутите колесо…» нет, поверх — надпись «still under construction». Лента с надписью поперёк карусели заказчику не понравилась. Когда придут чертежи башни, поле убрать.

Открытие — перелёт листа из миниатюры в центр (Web Animations: `transform` картинки + `opacity` у `::backdrop`, подписи проявляются следом), закрытие (крестик, фон, Esc — событие `cancel` перехватывается) — обратно в миниатюру; если миниатюра вне окна — просто проявление/растворение. Размер листа в просмотре задаётся через `cqw/cqh` и `--ratio`, чтобы перелёт считался до загрузки картинки, а под ней пока лежит уже загруженная миниатюра. Подпись (проект · «Лист NN · название») по центру над листом, счётчик и крестик справа. Колесо приближает лист к точке под курсором (до `ZOOM_MAX`, плавный доезд `ZOOM_TAU`) и не прокручивает страницу под `<dialog>` (раньше прокрутка проходила сквозь него); приближенный лист тянется мышью/пальцем, щипок — приближение, двойной клик — приблизить/вернуть целиком, клавиши `+`/`-`/`0`; свайп листает листы только при исходном масштабе; при смене листа масштаб сбрасывается.
